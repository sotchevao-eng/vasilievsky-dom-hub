# Сайт ТСЖ «Васильевский»

Современный адаптивный сайт-визитка и сервис для жителей: новости, документы, собрания, памятки, обращения. Контент управляется через админку, данные хранятся в Lovable Cloud.

## Визуальный стиль

Тёплая палитра сообщества: кремовый/бежевый фон, приглушённый зелёный как основной, терракота как акцент, мягкий коричневый, тёмно-зелёный текст, белые карточки. Мягкие скругления, лёгкие тени, много воздуха, аккуратные иконки. Все цвета — семантические токены в дизайн-системе, чтобы стиль менялся в одном месте.

Иллюстрации (генерируются): тёплая иллюстрация дома и благоустроенного двора для hero, домовой Василий — только на главной и в блоке «Полезно жителям». На страницах документов, контактов, политики персонажа нет.

## Страницы

- `/` — hero, важное объявление, 6 быстрых разделов, последние новости, полезно жителям, последние документы, «Информация со стенда», форма обратной связи
- `/news` — список с поиском и фильтром по категориям (Объявления, Работы, Благоустройство, Важно, Полезное)
- `/news/$slug` — страница новости
- `/residents` — сетка памяток (9 материалов), `/residents/$slug` — страница памятки
- `/documents` — архив с поиском, фильтром по категории и году, кнопки «Открыть» / «Скачать»
- `/meetings` — предстоящие и архив, `/meetings/$slug` — повестка, документы, результаты
- `/about` — о товариществе, правление, реквизиты, режим работы
- `/contacts` — адрес, телефон, email, приём, аварийные контакты, кнопки «Позвонить» / «Написать»
- `/privacy` — политика конфиденциальности, 14 разделов
- `/personal-data-consent` — согласие на обработку данных
- `/stand` — информация со стенда
- `/admin` — вход для правления и управление контентом

Все данные — плейсхолдеры в квадратных скобках ([адрес дома], [телефон ТСЖ], [ФИО председателя], [ИНН] и т. д.), без выдуманных реквизитов и дат.

## Админка

Вход по email/паролю для членов правления. Роли хранятся отдельно от профилей, доступ к редактированию — только для роли admin.

Разделы админки: новости, памятки жителям, документы (загрузка файлов), собрания, материалы стенда, настройки сайта (контакты, реквизиты, режим работы, важное объявление), входящие обращения.

В админке — заметка: «Перед публикацией Политики конфиденциальности рекомендуется проверить текст с учётом фактически используемых на сайте сервисов, форм, аналитики и способов обработки персональных данных.»

## Обращения жителей

Форма: имя, номер квартиры (необязательно), телефон или email, тема, сообщение. Чекбокс согласия — не отмечен заранее, кнопка отправки заблокирована без него. Рядом ссылки на политику и согласие. Валидация полей, после отправки — «Спасибо! Ваше обращение отправлено.» Обращения сохраняются в базе и видны только правлению.

## Cookie

Используются только технически необходимые cookie (сессия входа), аналитики нет — навязчивый баннер не добавляем. В политике это описано отдельным разделом.

## Компоненты

Header (компактный при прокрутке, burger-меню на мобильных, кнопка «Обратиться в ТСЖ»), Footer (тёмно-зелёный, ссылки, контакты, дисклеймер), NewsCard, DocumentCard, InfoCard, ImportantNotice, ContactForm, SectionTitle, Breadcrumbs.

## Доступность и адаптивность

Mobile first: одна колонка, крупные кнопки и поля. Контрастный текст, видимые focus-состояния, alt-тексты, корректная иерархия H1–H3, подписи полей форм, навигация с клавиатуры.

## SEO

Свой title/description/Open Graph на каждой странице, og:image для главной (для красивых ссылок во ВКонтакте), понятные URL, sitemap и robots.

## Техническая часть

- Lovable Cloud: таблицы `news`, `resident_guides`, `documents`, `meetings`, `stand_items`, `site_settings`, `inquiries`, `profiles`, `user_roles` (+ enum `app_role` и security-definer функция `has_role`)
- RLS: публичное чтение только опубликованного контента; запись и чтение обращений — только для admin; storage-бакет для файлов документов и изображений новостей
- Демо-строки с плейсхолдерами вставляются миграцией, чтобы страницы сразу были наполнены
- Чтение — через серверные функции/публичный клиент с SSR-загрузкой в loader'ах, запись — через авторизованные серверные функции с валидацией zod
- Первый зарегистрировавшийся получает доступ к админке через выдачу роли; далее роли назначает admin
